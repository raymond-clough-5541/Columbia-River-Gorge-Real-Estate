## Step 0: Environment facts (read before running anything)

1. **The Z.ai sandbox ships a template dev server on port 3000** (a generic
   Next.js template — NOT this project). Step 2/3 kills it. Port 3000 is
   single-occupancy and the ONLY port the user can see (preview panel).
2. **The dev server must run in the background** with `NODE_OPTIONS=
   "--max-old-space-size=2048"` — the 1024MB default crashes Next.js 16
   Turbopack; foreground processes die with the shell. Use
   `bash scripts/dev.sh` (setsid --fork daemon) — never bare `bun run dev`
   from a session you expect to outlive.
3. **The user sees only the `/` route.** This app is a single-route SPA
   with addressable hash fragments (`#/matrix`, `#/projections`,
   `#/listings`, `#/submarket/<slug>`) — never add page routes.
4. **`dev.log` at the repo root is the log source of truth** — read the
   RECENT tail only (it grows across sessions).
5. **All API/websocket URLs are relative** (`/api/…`, plus
   `?XTransformPort=<port>` for mini-services) — absolute localhost URLs
   bypass the one-port gateway and die.
6. **`z-ai-web-dev-sdk` is backend-only** (API routes / mini-services).
7. **Container rollbacks happen.** Symptoms: local `main` on an old chain,
   `git pull --ff-only` fails, `.git/auto-push.log` shows rejections,
   hooks silently unarmed. The remote is ALWAYS the source of truth —
   follow the playbook in `docs/REDEPLOY.md`, never ad-hoc recovery.
8. **Display-redaction trap:** the PAT may display as
   `[REDACTED:github_token]` even when a file really contains it — that is
   why Step 1 reconstructs it from base64.

## Step 2: Bootstrap the repo (fresh sandbox)

```bash
cd /home/z/my-project

# Kill the template dev server (it owns port 3000)
pkill -f "next dev" 2>/dev/null; pkill -f "next-server" 2>/dev/null; sleep 2

# Replace the template .git with the real repo (IN PLACE — the sandbox dir
# is never empty, so `git clone <url> .` fails; this preserves node_modules)
rm -rf .git
git init -b main
git remote add github "https://x-access-token:${PAT}@github.com/KeyWolfpack/fsbo.git"
git remote add origin "https://x-access-token:${PAT}@github.com/KeyWolfpack/fsbo.git"
git fetch github main
git reset --hard FETCH_HEAD
git branch --set-upstream-to=github/main main
```

**If the sandbox is a ROLLED-BACK container** (repo already checked out,
local behind the remote): do NOT bootstrap — go straight to Step 3
(redeploy.sh pull mode handles it; full playbook in `docs/REDEPLOY.md`).

## Step 3: Deploy (both modes) — this also ARMS THE GIT HOOKS

```bash
PAT="$PAT" bash scripts/redeploy.sh          # pull + install + hooks + db + dev + verify
# or, on a corrupted tree: PAT="$PAT" bash scripts/redeploy.sh --fresh
```

What it does: resolves + live-verifies the PAT → syncs to network truth →
`bun install` (which runs the `prepare` script → `git config core.hooksPath
scripts/git-hooks` → **the hooks are armed automatically**) → Prisma
generate + db push → arms hooks again (idempotent) → starts the dev server
via `scripts/dev.sh` (unless :3000 is already serving) → verifies
`GET /api/stats → 200`.

## Step 4: Verify the hook stack is armed (one command)
