# Portable Progress-Report PDF

> Copy this folder into any project when you need to explain progress to
> a **non-technical stakeholder in a medium that travels**: a
> self-contained PDF with a screenshot at every claim, zoomable to full
> capture resolution, readable offline on any device. Extracted R87 per
> DR-14 from the Free Trader instance (`scripts/report-pdf/`).

## Why this exists (the failure class it prevents)

- **Web-only review surfaces die with the workspace.** A progress report
  served by a local port (gallery, dev server) only works while that
  service runs. Stakeholders need a file they can open next month, on a
  phone, with no sandbox.
- **Prose-only reports cannot carry a UI.** A non-technical reviewer
  cannot assess an interface from text; every claim must sit next to the
  screenshot that evidences it, at a size worth looking at.
- **Review artifacts leaking into product/repos.** The PDF *embeds
  screenshots*, so it is itself a screenshot artifact: generated locally,
  delivered to a download folder, **never committed or pushed** (the
  Free Trader rules DR-13/DR-21; adopt equivalents). Only the generator
  tooling is committed.

## The pattern

- **Engine** (3 files, ReportLab + Playwright + pypdf):
  - `cover.html`: Template-01 cover (thick left anchor line, subtle
    grid, kicker/hero/summary/meta drawers) rendered by the pdf skill's
    `html2poster.js --width 794px` to a single A4 page.
  - `generate_report.py`: the body. `TocDocTemplate` + `multiBuild`
    clickable TOC; front-matter roman + body-arabic-reset page numbers;
    header/footer furniture; builder helpers (chapter/h2/h3/para/
    callout/stat_strip/area_card/shot_figure/data_table). Screenshots
    embed at full capture resolution (any PDF reader's zoom = large
    mode).
  - `build_final.py`: merges cover + body into one A4-normalized PDF
    with metadata.
- **One seam set** (env vars): `REPORT_SHOTS` (corpus folder),
  `REPORT_OUT_DIR`, `REPORT_TITLE`, `REPORT_AUTHOR`, `REPORT_SUBJECT`.
- **Content is the rewriteable part**: the story section of
  `generate_report.py` is the Free Trader R87 report (guided tour with a
  shot per step, honest frontend/backend progress cards, how-it-is-built
  and how-it-is-tested chapters, open asks WITH recommendations,
  plain-language glossary). Keep the engine, rewrite the story; keep the
  every-claim-next-to-its-screenshot discipline.

## Build + QA procedure

```bash
# 1. cover -> cover.pdf (html2poster preserves absolute positioning)
node <pdf-skill>/scripts/html2poster.js cover.html --output cover.pdf --width 794px
node <pdf-skill>/scripts/cover_validate.js cover.html        # overlap check
# 2. body -> body.pdf
python3 <pdf-skill>/scripts/pdf.py code.sanitize generate_report.py
python3 generate_report.py
# 3. merge + brand + clean
python3 build_final.py
python3 <pdf-skill>/scripts/pdf.py meta.brand final.pdf
python3 <pdf-skill>/scripts/pdf.py pages.clean final.pdf -o final_clean.pdf
# 4. QA gates (all must pass)
python3 <pdf-skill>/scripts/pdf.py font.check final.pdf
python3 <pdf-skill>/scripts/pdf.py toc.check final.pdf
python3 <pdf-skill>/scripts/pdf_qa.py --skip-cover final.pdf
# 5. visual pass: render key pages (cover/TOC/tour/cards/stats/last)
#    to PNG and eyeball or VLM them for overlap/void defects.
```

Palette: generated by `<pdf-skill>/scripts/pdf.py palette.cascade --title
"<doc title>" --mode minimal --format reportlab` (one cascade palette
feeds cover + body + tables + bars). Never hand-pick hex values.

## Deliverable rules

- PDF goes to a **download/delivery folder**, never `public/`, never
  `src/app/`, never committed (it embeds screenshots).
- Generator + cover HTML ARE committed (tooling, no screenshots inside).
- Numbers in progress bars must derive from a named, current source;
  gaps are stated, never hidden.
- Every open ask ships with a recommended option + reasoning (the
  Free Trader DR-23 rule; adopt it).
